Дүгнэлт (Хэсэг E)
Энэхүү 60 минутын exploratory тестийн сессийн явцад Fed-Ex Tour (Business District) болон Antisocial Tour (Seedy District) гэсэн хоёр өөр дүүргийн аялалыг хослуулан ашигласан нь маш үр дүнтэй байлаа. Тухайлбал, шинэ ном бүртгэх өгөгдлийн замыг мөшгөсөн Fed-Ex аялалын үеэр хүснэгтийн «Он» багана мянгатын таслалтай харагдах (BUG-01), «Устгах» товч улаан биш ногоон өнгөтэй байх (BUG-02), мөн «Нийт ном» тоолуур бодит мөрийн тооноос 1-ээр илүү гарах (BUG-03) зэрэг UI болон өгөгдлийн тооцооллын гурван согогийг илрүүлсэн. Харин дүрэм зөрчсөн оролт өгөх Antisocial аялалын үеэр curl -i ашиглан POST /api/books руу эвдэрсэн JSON бие илгээхэд 400 Bad Request-ийн оронд 200 OK буцаадаг API түвшний согогийг (BUG-04) баталгаажуулав. Charter-аас гадуур ажиглахад хуудасны доод хэсэгт «Хуучин хувилбар» гэсэн сэжигтэй линк байгааг анзаарсан ч хугацааны хязгаараас шалтгаалан тухайн линк, мөн том/жижиг үсэг ялгах хайлт, давхардсан ном бүртгэх хилийн тохиолдлууд бүрэн шалгагдаагүй үлдсэн тул дараагийн сессийн charter-т оруулах шаардлагатай. Илрүүлсэн эдгээр согогоос BUG-03 (тоолуурын математик зөрүү) болон BUG-04 (API HTTP статус код 400 vs 200) нь тодорхой утга ба статус кодыг шалгадаг тул Playwright автомат тестээр хялбар баригдах боломжтой. Харин BUG-02 («Устгах» товч аюултай үйлдэл атлаа ногоон өнгөтэй байж хэрэглэгчийг төөрөгдүүлэх) болон BUG-01 (онууд 1,999 гэж таслалтай харагдах визуал таагүй байдал) нь хүний нүд, UX мэдрэмжээр хамгийн түрүүнд анзаарагдах согогууд байв.
